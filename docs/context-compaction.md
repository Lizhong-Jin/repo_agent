# 上下文压缩与历史回查

[文档首页](index.md) · [项目首页](../README.md) · [会话管理](sessions.md) · [配置参考](configuration.md)

## 使用方式

在会话中输入 `/compact` 手动压缩。普通终端和全屏界面都会显示摘要进度及前后 token 粗估值，Ctrl+C 可以取消。没有足够旧历史时提示无需压缩。

默认启用自动压缩：每次正常模型请求前检查完整输入，包括当前系统指令、技能目录、工具定义和本轮新增消息。工具调用的全部结果返回后也会检查，因此单条长任务执行过程中可以压缩。

达到触发阈值不代表必须先完成一次压缩：新会话首次长输入等场景没有旧历史可压缩时，只要完整输入仍在安全预算内，就原样继续模型请求；超过安全预算则提示拆分输入。归档损坏、保存失败等真实错误仍会中止，不会被当成无需压缩。

```bash
repo-agent --auto-compact false               # 本次关闭自动压缩，仍可手动执行
repo-agent --compact-threshold 0.8 --compact-target 0.5
repo-agent config set AGENT_AUTO_COMPACT false # 保存后重启生效
```

CLI 接入的压缩器与 `CompactionSettings` 共用默认值（单独使用 `AgentRuntime` 不会自动启用压缩）：触发比例为 0.75，目标比例为 0.45，二者相对于**可用输入预算**：完整窗口上限减去本轮输出预留；服务端提供输入专用上限时直接使用该输入上限。上限未知时不自动压缩，手动压缩会提示先使用 `/context auto` 或 `/context 数值`。启用自动压缩且上限已知时，预算不足会停止并说明配置问题。关闭自动压缩或上限未知时，该自动检查不提供输入超限拦截。

`AGENT_COMPACT_KEEP_TOKENS=6000` 控制近期原文预算上限，实际预算为 `min(keep_tokens, max(256, target_tokens // 3))`；这里 `target_tokens` 是可用输入预算乘以目标比例后取整，最低为 1。`AGENT_COMPACT_MAX_REFINEMENTS=2` 控制超出目标后的额外精简轮数，可设为 0～4；`--compact-max-refinements` 可覆盖本次启动配置。配置在重启时重新读取，不随旧快照覆盖。

`AGENT_COMPACT_SUMMARY_TOKENS` 和 `--compact-summary-tokens` 已弃用：旧值仍兼容读取，但完全忽略，不再设置摘要独立硬上限。启动时会提示迁移，可以删除这些旧配置。

## 保留和压缩哪些内容

工作上下文由当前系统消息、用户原文交接资料、结构化摘要和近期消息组成。

- 程序按出现顺序保留被移出近期范围的用户消息原文、引用及事件标识。相同文本的重复发言也保留，例如“中文 → 英文 → 中文”不能去重成“中文 → 英文”。原文可能包含引用资料；提示明确它不构成新增授权，用户后续更正优先。
- 模型概括目标、约束、进度、决策、文件状态、验证结果和下一步；各条结论必须引用本次提供的档案记录。
- 近期消息按完整消息组保留，助手工具调用及其全部返回结果不会被拆开。保留的供应商原生状态保持原样。
- 若最新一个完整工具组本身超出近期预算，会整体归档并摘要，保留最近用户请求原文。这次发言只作为近期消息保留，不同时加入原文交接列表，避免后续压缩重复计入同一次事件。原始工具结果可回查。
- 长历史按预算分段生成摘要，再按栏目合并。分段规划只增量估算新记录，避免反复扫描已累积的历史；每次发送前仍重新估算完整请求并检查窗口。分段和输出有预算限制；无法容纳时明确报错，不强制截掉用户原话。
- 后续压缩沿用已有用户原文，更新历史摘要。旧摘要也归档，其引用可以逐级追到原始记录。
- 每段请求只向模型提供 `R1`、`R2` 等短引用，校验后由程序映射回真实档案引用再保存。旧摘要或工具正文内嵌的长引用在本次请求中替换为其所在记录的短引用；真实归档保持原样。正文里出现其他档案 ID 不会扩展本次允许引用的来源。

## 独立请求参数

摘要使用当前模型，通过独立、无工具的请求生成。思考参数来自 `llm/model_catalog.py` 中每个模型的 `independent_thinking`，不沿用 session 的 `/thinking`、思考预算、温度、原生扩展参数或输出上限。模型切换后使用新模型的目录配置。此策略封装在 `llm/independent.py`，其他内部独立请求也可复用。

目录配置示例：

```python
independent_thinking={"mode": "enabled", "effort": "low"}
# 固定预算模型：{"mode": "enabled", "budget": 2048}
# 自适应思考模型：{"mode": "adaptive", "effort": "low"}
```

有强度档位时默认选择最低可用档位；固定预算模型默认使用 2048（不超过目录范围）；只有开关的可关闭模型使用 disabled；其余保留 auto。按模型实际支持的参数修改此字段，重启后生效。

输出额度从目录 `max_output_tokens` 的 **25%** 起步，初始值通常限制在 **8192～32768** 之间，同时不超过模型上限。固定思考预算需要为正文至少留出 1024。只有返回 `length` 截断时才将额度翻倍重试，最多加大 4 次；始终受目录上限和当前窗口剩余空间约束。额度是上限，并非必定消耗的 token 数。输出上限未知的模型保守使用 8192，不自动猜测更高上限。

例如当前目录中的 `deepseek-flash` 最大输出为 393216，独立请求采用 low：额度依次可为 32768、65536、131072、262144、393216；未截断就不会继续增加。输入很长时会先分段，小窗口会进一步缩小实际输出额度；输入专用窗口不扣减输出。

## 目标和采纳规则

`target` 指导**整个新工作上下文**的大小，包括系统/工具/技能信息、用户原文、摘要和近期消息。模型收到扣除固定部分后的摘要目标，但该数值只用于指导生成，不作为独立硬限制。压缩较短上下文时，以配置目标和原上下文 75% 中较小者减去固定部分，作为摘要的生成目标（最低 256 tokens）。在此基础上，摘要正文目标还取独立请求初始输出额度的 1/4（最低 256、最高 8192）与上述目标的较小值，避免大窗口下生成冗长摘要。常见初始额度 8192～32768 对应正文目标 2048～8192。分段时按段数分摊，每段最低 128。所有这些数值都是软目标：超过摘要正文目标不会直接拒绝，仍按整个新上下文的大小决定是否采纳，也不保证必定缩小到原来的 75%。

生成摘要后，程序估算完整新上下文；超过目标时最多再精简两轮（可配置），始终保留其中最小的合法候选。进一步精简失败时也会检查已有候选。

- 达到目标、确实缩小且满足安全空间要求：采纳。
- 有限精简后仍超过目标，但至少缩小 **10% 且减少 256 tokens**，并满足安全空间要求：采纳，明确显示“未达到目标，已采用有效缩减结果”。
- 不满足采纳条件、原始摘要无效或取消：保留原上下文。

完整窗口的安全检查会预留待发送请求的输出额度（包括工具参数重生成时提高的额度）；输入专用上限不扣输出额度。两种口径都保留额外的输入余量：可用输入预算的 5%，最少 1024、最多 8192 tokens。该检查基于本地估算，不能保证供应商永不拒绝超限请求。

采纳后，自动压缩要等上下文再增长可用输入预算的 5%（至少 1024 tokens）才再次触发，避免反复压缩；接近安全边界时绕过此等待门槛。门槛随会话保存，重启仍生效；手动 `/compact` 不受此限制。

摘要正文不作为正常 Agent 回复显示。请求用量计入会话总计，但不消耗任务执行轮数，也不重置已有统计。用量缺失时沿用“部分已知”的统计口径。

## 原始记录保存与恢复

在会话状态的项目目录下新增 `history.sqlite3`，首次压缩归档时创建：

```text
${XDG_STATE_HOME:-~/.local/state}/repo-agent/sessions/<项目路径哈希>/
  history.sqlite3      # 该项目各会话的原始消息和有序快照
  <会话ID>.json        # 当前工作上下文、压缩元数据、用量及界面记录
  <会话ID>/compaction-diagnostics/<诊断ID>.json  # 失败候选及引用映射（失败时创建）
```

档案保存消息正文、工具调用/返回和供应商原生状态；相同会话中完全相同的消息内容去重，有序快照保留每次出现的位置和次数。引用格式为 `会话ID/m消息编号`，不会因后续压缩、改名或重启改变。时间字段表示归档时间。macOS/Linux 档案目录权限 700、数据库文件权限 600；Windows 继承用户目录 ACL，这些权限值不表示已经设置 Windows 私有 ACL。

内容引用标识原文对象，不能用来判断发言是否属于同一次事件。压缩元数据 `pins` 另存 `occurrence`（快照 ID＋从 0 开始的消息位置），后续压缩及恢复继续保持已有事件的顺序。旧版没有该字段的会话兼容读取，已有摘要不会自动重写；旧压缩中已被省略的重复更正不在本次自动修复范围内，需检查归档数据库中的原始有序快照核实。`history_search` / `history_read` 按内容记录回查，不提供消息出现顺序的重建接口。

先提交原始档案，再请求摘要；摘要结构、引用、消息合法性及缩短幅度通过检查后，才保存并替换工作上下文。没有可采纳摘要、取消或存储失败时保留原上下文；已经返回的摘要请求用量仍计入统计。自动压缩失败会停止当前任务，保留最近完整历史及中断说明，可调整配置后继续。重启检查原文档案存在且快照完整，再加载压缩后的上下文，无需再次生成摘要。

压缩不会修改项目代码、文档或沙箱工作副本。`chat.log` 和 trace 日志仍用于阅读，不承担完整消息备份。迁移时一起保留项目状态目录；档案内容不会随普通快照覆盖而丢失。没有自动删除档案或清理旧会话的策略。

## 校验失败、有限修复与诊断

程序分别校验 JSON、七个栏目、条目字段、正文和引用。允许单层完整的 JSON 代码围栏；不从混杂解释中猜测或截取 JSON，不接受重复字段、NaN/Infinity、顶层数组、未知来源或空摘要。

首次格式或引用校验失败时，先保存失败候选，再尝试**一次修复请求**。该请求包含候选、具体错误、当前允许的短引用、每条来源最多 512 字符的片段，以及候选中出现的已知真实引用到短引用的映射；不会重发完整原始历史。提示要求保留事实、约束和不确定性，不能通过删除不支持的条目或随意替换引用来通过校验。来源不足以确定引用时仍应拒绝采纳。修复后执行同样的完整校验。

一次修复的限制针对每个失败的分段请求，也适用于精简轮次。修复调用使用相同的模型目录独立思考和初始输出策略，且不再因截断重试；修复请求放不进窗口、调用失败、截断或校验仍不通过时结束。正常摘要和精简请求的输出截断仍按前述额度增长策略处理；耗尽后记录失败候选，不再做格式修复。异常结束原因、档案损坏等不是格式问题，不触发格式修复。已经有合法摘要的后续精简失败时，仍可按采纳规则使用已有候选。

所有已返回的摘要、修复和精简调用用量都计入累计统计；取消或最终失败不会清零。没有可采纳候选时保留原工作上下文。

界面和执行日志显示错误类别、字段位置和诊断 ID。例如 `REF_NOT_ALLOWED progress[0].refs[0]` 表示该引用不在当前请求允许的来源中。主要类别：

| 类别 | 含义 |
| --- | --- |
| `JSON_PARSE` / `DUPLICATE_KEY` / `JSON_CONSTANT` | JSON 解析失败、重复字段或非法常量 |
| `ROOT_TYPE` / `SECTION_KEYS` / `SECTION_TYPE` | 顶层或栏目结构错误 |
| `ITEM_FIELDS` / `TEXT_TYPE` / `REFS_TYPE` | 条目、正文或引用列表类型错误 |
| `REF_NOT_ALLOWED` / `EMPTY_SUMMARY` | 引用越界或摘要没有有效条目 |
| `OUTPUT_TRUNCATED` / `FINISH_REASON` | 输出被截断或响应未正常结束 |
| `REPAIR_REQUEST_FAILED` | 唯一一次修复请求无法完成 |

失败候选正文、真实引用映射、错误、模型信息、用量和档案快照 ID 保存到上面的 `compaction-diagnostics` 目录。初次失败和修复失败分别保存，文件名对应诊断 ID；修复成功也保留初次失败记录以供排查。macOS/Linux 目录权限为 700、文件权限为 600；Windows 继承目录 ACL，并通过句柄操作拒绝重解析点。目录符号链接会被拒绝。保存诊断失败会明确提示，不会显示不存在的诊断 ID。

普通 `chat.log` / trace 日志不写失败候选正文和引用映射；诊断文件不通过 `history_read` / `history_search` 暴露。诊断内容可能含历史中的敏感文字，分享排错材料前应检查并脱敏。没有自动清理策略，可在排查完成后删除相应诊断文件，不影响工作上下文或原始档案。

## Agent 如何回查

CLI 会话始终注册两个主进程只读工具（单独使用 Runtime 的调用方需自行装配），local/native/docker 模式行为一致：

- `history_search(query, session="current", offset=0, limit=8)`：不区分大小写的子串搜索，支持中文、文件路径、函数名和错误文本；返回原文引用、角色、片段及分页位置。`session="project"` 查询本项目全部已归档会话，也可指定本项目会话 ID。
- `history_read(reference, offset=0, limit=4000)`：按字符偏移读取档案正文和工具调用参数。实际每页最多 1200 字符，返回 `next_offset`；继续读取时使用该偏移。供应商原生内部状态不向模型暴露。

摘要缺少细节、用户要求核对原话，或需要查看精确错误时，Agent 可先搜索，再读取相应片段。查询仅覆盖**已经归档**的消息；尚未压缩的旧会话不会自动导入。

回查结果作为有来源的工具结果进入当前上下文，不重放工具调用，也不将历史文字升级为系统指令或新增授权。修改文件前仍应读取当前文件。普通文件工具继续禁止直接访问会话状态目录；专用工具只接受记录引用，不接受任意文件路径。

## 限制

token 数使用本地粗估，并非模型专用 tokenizer，也无法准确计算供应商隐藏状态；触发阈值预留空间，但不能保证服务端永不拒绝超限请求。摘要是有损操作，结构校验不能保证语义完全无遗漏。用户原文太多、单条任务太大或固定系统/工具信息过大时可能无法达到目标，此时需要调整预算、精简任务或开启新会话。
