# 上下文压缩与历史回查

[返回 README](../README.md) · [会话管理](sessions.md) · [配置参考](configuration.md)

## 使用方式

在会话中输入 `/compact` 手动压缩。普通终端和全屏界面都会显示摘要进度及前后 token 粗估值，Ctrl+C 可以取消。没有足够旧历史时提示无需压缩。

默认启用自动压缩：每次正常模型请求前检查完整输入，包括当前系统指令、技能目录、工具定义和本轮新增消息。工具调用的全部结果返回后也会检查，因此单条长任务执行过程中可以压缩。

```bash
repo-agent --auto-compact false               # 本次关闭自动压缩，仍可手动执行
repo-agent --compact-threshold 0.8 --compact-target 0.5
repo-agent config set AGENT_AUTO_COMPACT false # 保存后重启生效
```

默认触发比例为 0.55，目标比例为 0.20，二者相对于**可用输入预算**：完整窗口上限减去本轮输出预留；服务端提供输入专用上限时直接使用该输入上限。上限未知时不自动压缩，手动压缩会提示先使用 `/context auto` 或 `/context 数值`。预算不足时停止并说明配置问题。

`AGENT_COMPACT_KEEP_TOKENS=6000` 控制近期原文预算上限，实际不超过目标预算的约三分之一。`AGENT_COMPACT_SUMMARY_TOKENS=3000` 控制最终摘要正文的目标预算（包含 JSON 与引用），不再作为模型请求的输出上限。两项至少为 256。配置在重启时重新读取，不随旧快照覆盖。更多参数见配置参考。

## 保留和压缩哪些内容

工作上下文由当前系统消息、用户原文交接资料、结构化摘要和近期消息组成。

- 程序保留被移出近期范围的所有用户消息原文及引用。原文可能包含引用资料；提示明确它不构成新增授权，用户后续更正优先。
- 模型概括目标、约束、进度、决策、文件状态、验证结果和下一步；各条结论必须引用本次提供的档案记录。
- 近期消息按完整消息组保留，助手工具调用及其全部返回结果不会被拆开。保留的供应商原生状态保持原样。
- 若最新一个完整工具组本身超出近期预算，会整体归档并摘要，保留最近用户请求原文。原始工具结果可回查。
- 长历史按预算分段生成摘要，再按栏目合并。分段和输出有预算限制；无法容纳时明确报错，不强制截掉用户原话。
- 后续压缩沿用已有用户原文，更新历史摘要。旧摘要也归档，其引用可以逐级追到原始记录。

摘要使用当前模型，通过独立、无工具的请求生成。每次请求继承运行时当前有效的思考模式、强度、预算及温度；配置文件、`/thinking`、Shift+Tab 和模型切换后的设置都会生效，`LLM_EXTRA_JSON` 中受支持的原生思考参数也会沿用。摘要不继承任务特定的输出格式、停止词、工具或技能目录。

每个摘要请求的输出上限使用 `AGENT_MAX_OUTPUT_TOKENS` / `--max-output-tokens`，为思考和正文提供与普通请求一致的额度。`AGENT_COMPACT_SUMMARY_TOKENS` 则约束最终摘要大小：分段时分配目标，生成后按本地粗估校验总大小；超过目标时保留原上下文。完整窗口的输入预算会扣除实际输出预留；服务端给出的输入专用上限不重复扣除。`auto` 思考模式仍沿用服务端默认行为。

例如输出上限为 51200、摘要目标为 3000 时，每个摘要请求最多可生成 51200 token（包含接口计入输出的思考），最终保留的摘要仍需满足约 3000 token 的目标。额度是上限，不代表每次必定消耗这么多。若仍因输出额度耗尽中断，错误信息会显示结束原因、请求上限及服务端报告的输出/思考用量。

摘要正文不作为正常 Agent 回复显示。请求用量计入会话总计，但不消耗任务执行轮数，也不重置已有统计。用量缺失时沿用“部分已知”的统计口径。

## 原始记录保存与恢复

在会话状态的项目目录下新增 `history.sqlite3`，首次压缩归档时创建：

```text
${XDG_STATE_HOME:-~/.local/state}/repo-agent/sessions/<项目路径哈希>/
  history.sqlite3      # 该项目各会话的原始消息和有序快照
  <会话ID>.json        # 当前工作上下文、压缩元数据、用量及界面记录
```

档案保存消息正文、工具调用/返回和供应商原生状态；相同会话中完全相同的消息内容去重，有序快照保留每次出现的位置和次数。引用格式为 `会话ID/m消息编号`，不会因后续压缩、改名或重启改变。时间字段表示归档时间。档案目录权限 700、数据库文件权限 600。

先提交原始档案，再请求摘要；摘要结构、引用、消息合法性及缩短幅度通过检查后，才保存并替换工作上下文。摘要失败、取消、目标无法满足或存储失败时保留原上下文；已经返回的摘要请求用量仍计入统计。自动压缩失败会停止当前任务，保留最近完整历史及中断说明，可调整配置后继续。重启检查原文档案存在且快照完整，再加载压缩后的上下文，无需再次生成摘要。

压缩不会修改项目代码、文档或沙箱工作副本。`chat.log` 和 trace 日志仍用于阅读，不承担完整消息备份。迁移时一起保留项目状态目录；档案内容不会随普通快照覆盖而丢失。没有自动删除档案或清理旧会话的策略。

## Agent 如何回查

Agent 始终可使用两个主进程只读工具，local/native/docker 模式行为一致：

- `history_search(query, session="current", offset=0, limit=8)`：不区分大小写的子串搜索，支持中文、文件路径、函数名和错误文本；返回原文引用、角色、片段及分页位置。`session="project"` 查询本项目全部已归档会话，也可指定本项目会话 ID。
- `history_read(reference, offset=0, limit=4000)`：按字符偏移读取档案正文和工具调用参数。实际每页最多 1200 字符，返回 `next_offset`；继续读取时使用该偏移。供应商原生内部状态不向模型暴露。

摘要缺少细节、用户要求核对原话，或需要查看精确错误时，Agent 可先搜索，再读取相应片段。查询仅覆盖**已经归档**的消息；尚未压缩的旧会话不会自动导入。

回查结果作为有来源的工具结果进入当前上下文，不重放工具调用，也不将历史文字升级为系统指令或新增授权。修改文件前仍应读取当前文件。普通文件工具继续禁止直接访问会话状态目录；专用工具只接受记录引用，不接受任意文件路径。

## 限制

token 数使用本地粗估，并非模型专用 tokenizer，也无法准确计算供应商隐藏状态；触发阈值预留空间，但不能保证服务端永不拒绝超限请求。摘要是有损操作，结构校验不能保证语义完全无遗漏。用户原文太多、单条任务太大或固定系统/工具信息过大时可能无法达到目标，此时需要调整预算、精简任务或开启新会话。
