# 执行日志与文件保护

[返回 README](../README.md)

本文中的命令默认在 Agent 安装目录执行；任务项目目录会单独注明。

## 日志文件

启动脚本在任务目录的 `logs/`（或 `AGENT_LOG_DIR`）保存同一会话的三份文件：

| 文件 | 内容 |
| --- | --- |
| `session_时间_进程号.log` | 终端对话：用户输入、模型回复和必要错误提示 |
| `session_时间_进程号.trace.log` | 可读的执行记录：模型和工具调用、每条任务统计及会话汇总 |
| `session_时间_进程号.trace.jsonl` | 结构化事件，一行一个 JSON 对象，适合检索和后续分析 |

任务与会话的完整执行统计写入追踪日志；终端还会显示流式响应计时、工具进度和 token／上下文状态。

## 事件与统计口径

追踪实现统一位于 `agent/Tracing.py`：`RunTrace` 负责模型/工具执行计时与任务统计，`Tracer` 负责文件写入和会话汇总。Runtime 只在执行边界接入追踪，CLI 负责创建和关闭 `Tracer`。

每条自然语言输入视为一个任务，追踪记录包含：

- 模型调用：每次调用开始、结束、耗时、结束原因及 token 用量。
- 工具调用：对应模型轮次、工具名称、调用 ID、目标路径与参数摘要、成功/失败/中断状态、错误码和耗时。
- 任务汇总：模型调用次数、工具调用次数、失败/中断次数、token 累计及总耗时。正常结束、达到轮数上限、失败和 Ctrl+C 中断都会记录。
- 会话汇总：任务数量与状态分布、累计调用次数、token 用量，以及任务执行总耗时和包含输入等待的会话总耗时。

JSONL 包含 `schema_version`、带时区的 `timestamp`、`session_id` 和唯一的 `task_id`。事件类型包括 `session_start/end`、`task_start/end`、`model_start/end`、`tool_start/end` 和 `skill_loaded`。会话开始记录厂商、模型与工作区，不记录 API Key、系统提示词和完整请求。工具参数只保留路径、小型选项及正文长度，不重复输出文件正文、编辑片段或工具返回正文。

追踪文件权限为 `600`，每条事件立即 flush，创建时拒绝覆盖已有同名文件。运行期间追踪写入失败会停止写入，并在退出时显示必要错误提示，不会因此重试或撤销已经执行的文件操作。强制杀进程或断电时可能缺少结束事件；终端日志含控制字符，追踪日志也不是会话恢复文件。

直接运行 `repo-agent` 时同样生成两份追踪文件，但没有启动脚本负责录制的终端对话文件；未指定 `AGENT_LOG_DIR` 时追踪文件位于 `--root` 下的 `logs/`。启动脚本自动传递内部会话 ID，使三份文件使用相同文件名前缀，无需新增配置。

统计口径：每个任务从零累计，`/help`、`/clear`、退出指令和空输入不算任务。模型次数是 Runtime 调用模型接口的尝试次数，包括失败和中断，不单独统计 HTTP 层内部重试。耗时从开始执行任务到结束，包括模型等待、重试等待和工具执行，不包含用户输入等待。输入 tokens 包含 API 对历史上下文的本次计量；输出中的思考 tokens、输入中的缓存 tokens 是子项，不再额外加到合计中。服务端未返回用量时显示“未返回”；只有部分调用有用量时显示已知小计和覆盖次数，不把未知消耗当成零，也不等同于账单上的最终费用。

例如任务结束时会写入 `.trace.log`（终端不显示）：

```text
[时间] [任务 1] 统计：状态=completed，模型调用=3 次，工具调用=2 次（失败/中断 0 次），总耗时=8.421s
[时间] [任务 1] tokens：输入=1200，输出=300，合计=1500；缓存读取=500，缓存写入=未返回，思考=100
```

## 文件保护边界

文件工具与 Docker 导入/回写共用 `tools/file_policy.py` 的受保护名称规则：`.env` / `.env.*`（含模板）、`.git`、`.codex`、`.agents`、`logs`、常见凭据目录（`.ssh`、`.aws`、`.gnupg`、`.kube`、`.docker`）、`.npmrc`、`.pypirc`、`.netrc`、Git 凭据、常见 SSH 私钥名称及 `.pem/.key/.p12/.pfx/.jks/.keystore` 文件。任意层级匹配；`AGENT_ENV_FILE`、`AGENT_LOG_DIR` 及其子路径也受保护。文件工具检查符号链接原名和目标，拒绝多硬链接普通文件；目录列表和搜索过滤保护项。Git diff 先筛选变更路径再读取正文，目录范围同样过滤保护项，并禁用重命名检测，防止差异引用受保护来源。

这些规则防止常见误操作，不识别嵌入普通源码的密钥，也不为本地文件操作提供抵御并发恶意路径替换的操作系统隔离。`.gitignore` 不负责访问控制。请在编辑器中修改受保护配置；不受信任任务使用默认 Docker 模式。
