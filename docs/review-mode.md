# 只读审查模式（第一版）

```sh
repo-agent --root /path/to/project --new-session --mode review
repo-agent --root /path/to/project --new-session --mode review "检查异常处理和恢复流程"
```

审查模式保留受控的文件读取、搜索、目录查询和 Git 状态、差异、历史查询。禁止文件写入、补丁、移动、删除、通用命令、Shell、Python、语言服务器和测试执行。第一版也不注册 Web 工具；模型 API 请求继续正常联网。

无需初始化 Git，也可以审查未提交的修改。非 Git 目录可以读取文件，Git 查询会返回不适用。已有凭据和受保护路径规则继续生效。Git 查询拒绝项目目录中的同名可执行文件，并禁止隐式下载对象；部分克隆暂不支持。

## 权限和执行环境

`--mode develop` 是开发模式；省略 `--mode` 时，新会话使用开发权限，已有会话恢复自己的权限。审查模式采用受控宿主读取，不启动 native/Docker 命令后端，因此不会执行这些后端的预检、GPU 检测或项目 Python 探测。即使安装默认方式为 native/Docker，审查报告仍显示实际使用的 local 读取环境。

限制并非只依靠提示词或隐藏工具：工具注册和调用入口使用同一权限策略，仅接受已审查的具体实现，未知实现和子类默认拒绝；动态工具组不能增加权限。文件服务将整个审查目录标记为只读。Git 查询沿用受控参数、禁用自动行为和拒绝外部过滤器的本地路径，不开放任意 Git 命令。

这个模式不向项目代码提供执行入口，也不把宿主 Python 插件变成不可信代码沙箱。它不会锁住其他编辑器；外部并发修改仍可能影响审查结果。读取可能更新系统维护的访问时间，模型请求和应用自身状态也不属于“完全无副作用”的承诺。

## 会话、队列和报告

权限写入会话快照、任务尝试和交付报告。恢复会话、队列续跑、`/continue` 和 `/new` 保持审查权限；`/workspace` 显示当前权限和路径。审查报告明确说明没有运行命令或测试，静态结论不能当成测试通过。

```sh
# 恢复审查会话时不必重复指定模式
repo-agent --root /path/to/project --session 1
# 决定修复后，明确开启另一个开发会话
repo-agent --root /path/to/project --new-session --mode develop
```

已有会话不能用 `--mode` 改变权限；旧版本未记录权限的会话按 develop 处理。用户主动 `/switch` 到另一个会话时，加载目标会话自己的权限；模型没有切换权限的工具。

会话、账本和报告仍会保存到项目外的状态目录。审查追踪日志固定放在该项目会话目录的 `review-logs/`，不采用 `AGENT_LOG_DIR`，也不创建项目 `logs/`。若状态目录或用户配置目录位于被审查项目内，会拒绝启动，应先调整 `XDG_STATE_HOME` 或 `AGENT_CONFIG_DIR`。

## 与独立工作区配合

第一版审查任务不创建 worktree、不初始化仓库、不合并或回写。`--workspace worktree` 与审查模式不能同时使用。

审查已有独立工作区时，将它的实际路径作为项目根目录，建立独立的审查会话：

```sh
repo-agent --root /path/to/existing-worktree --new-session --mode review
```

这不会改变原开发会话的权限或工作区生命周期。先暂停开发任务可以获得更稳定的审查结果。需要运行测试或应用修复时，回到明确授权的开发会话处理。
