# 会话管理

[文档首页](index.md) · [项目首页](../README.md) · [日志查看](logging.md)

一个会话可以包含多条用户任务，也可以跨多次程序启动继续。程序按项目保存会话，默认恢复该项目最后一次会话，也可以用 `--session` 指定旧会话，或在交互界面用 `/switch` 切换。会话序号可用于恢复、列表、改名和日志查询。

## 会话命名与管理

新会话分配永久 ID 和项目内递增序号；未命名时显示为 `会话 1`、`会话 2`。自定义名称也占用一个序号，序号不回收（启动失败时可能跳号）。恢复上次会话、每次输入任务、`/clear` 都不会分配新名称或序号。

```bash
repo-agent --new-session --name "修复登录问题"
repo-agent --new-session                         # 默认名称
repo-agent sessions list
repo-agent sessions rename 12 "登录问题排查"
repo-agent sessions list --root /path/to/project
```

首次启动没有历史记录的项目时，也可以直接传 `--name`。已有会话时，`--name` 须配合 `--new-session`；恢复会话的改名使用 `/rename` 或 `sessions rename`。

界面命令：`/new [名称]`、`/rename 新名称`、`/sessions`、`/switch 序号或名称`、`/logs [序号] --tail 100`。名称支持中文和空格，长度为 1–80 个字符，不能包含换行或控制字符。支持重名；命令优先按序号或完整 ID 查找，再按名称精确查找，同名时列出候选序号。`latest` 表示默认恢复的会话。

TUI 顶部常驻会话名称与序号，按 **F2** 编辑名称，Enter 保存、Ctrl+C 取消；编辑前的输入草稿会保留。也可以用 `/rename` 改名。普通终端在每次输入前显示名称。另一个终端改名后，TUI 会在约一秒内更新标题；改名不会修改上下文、序号、日志路径或默认恢复的会话。

列表显示序号、名称、最近活动时间、是否正在运行以及是否默认恢复。查看列表和日志无需模型配置或 Docker，不占用 Agent 的执行锁；运行时也能在另一个终端查看或改名。管理命令支持 `--root`，也支持 `repo-agent --root /path sessions list`。

## 选择与切换已有会话

先查看当前项目的会话：

```bash
repo-agent sessions list
repo-agent --session 3                      # 按序号恢复
repo-agent --session "登录问题排查"           # 按完整名称恢复
repo-agent --session <完整会话ID>            # 按完整 ID 恢复
repo-agent --root /path/to/project --session 3
repo-agent --session 3 '继续检查测试结果'     # 在指定会话中执行一项新任务
```

普通终端和全屏界面都支持：

```text
/sessions
/switch 3
/switch "登录问题排查"
/switch <完整会话ID>
```

选择范围限于当前项目；支持序号、完整 ID、完整名称和 `latest`。名称包含空格时，命令行启动参数需要引号，界面命令也可加引号。存在同名会话时会列出候选序号，不会任意选择。切换到当前会话只提示，不清空历史或新建会话。`--session` 不能与 `--new-session` 或 `--name` 同用；改名请使用 `/rename`。

切换先保存当前会话，停止使用旧运行时，再重新建立目标会话的运行环境、日志和工具。恢复目标会话自己的上下文、压缩状态、显示记录、累计用量、工具组、任务队列和执行账本。模型、思考强度、输出设置沿用当前配置；手动上下文窗口按原有恢复规则处理，启动时显式指定的上限优先。切换成功后，目标会话成为该项目下次默认恢复的会话，原会话记录继续保留。

任务正在执行、正在收尾或进程清理尚未确认时不能切换。有等待任务时，先 `/queue pause` 保存暂停状态，再 `/switch`；不必删除这些任务。切回后队列仍处于暂停状态，通过 `/queue resume` 明确继续，不会自动重放旧任务。单次任务模式仍不允许插入已有等待队列。

切换过程中保留同一个项目执行锁。目标快照损坏、归档缺失或执行环境无法恢复时，交互切换会尝试重新打开已经保存的原会话；原会话恢复也失败时明确报错退出。当前会话保存失败或旧环境清理失败时停止切换。启动时显式选择的目标无法恢复，会直接报错，不悄悄改选其他会话。

**切换不回滚项目文件。** local/native 会话共享实际工作目录；Docker 会恢复目标会话记录的副本及回写基线，未回写修改继续保留，切换本身不会自动回写。通过界面 `/new` 创建的会话可能共享原副本；选择会话不会自动复制或合并这些副本。

## 保存、恢复与新会话

```bash
repo-agent                        # 默认恢复当前项目的最后一次会话
repo-agent --new-session          # 启动全新会话，保留旧会话记录
repo-agent --root /path/to/project # 恢复指定项目的最后一次会话
repo-agent '继续完成刚才的修改'      # 单次任务也会恢复并保存会话
```

会话内 `/new` 保存旧会话、清空显示历史与模型上下文并重置累计用量；文件修改和当前沙箱副本保留。`/clear` 清空模型上下文，保留显示历史和累计用量，清空结果也会保存；此前压缩产生的原文档案保留。没有历史记录的项目自动创建会话。不同项目相互隔离，以解析符号链接后的项目绝对路径作为标识；同一目录的符号链接共用会话，移动项目目录后视为不同项目。

macOS/Linux 会话记录目录权限为 `700`，文件权限为 `600`；Windows 文件继承所在用户目录的 ACL，不能把这些 POSIX 权限值视为 Windows 私有 ACL 保证。快照采用临时文件和原子替换保存。会话状态目录受文件工具与沙箱导入/回写保护。

每个任务执行前记录未完成标记，任务结束后保存有效历史，正常退出时再次保存。未传入新任务时，重启恢复状态后等待用户输入；显式传入任务时执行该新任务，不会重放历史工具调用。自动压缩前和采纳摘要时也会保存检查点。强制终止或断电后恢复到最后一次成功保存的检查点，可能位于任务中途，并说明中断任务可能已执行部分文件操作；检查点之后的工具执行证据由独立账本保存；外部效果发生而结果尚未落盘的窗口仍需核实，见[执行账本与恢复](execution-ledger.md)。用量以已保存的统计为准。保存失败会明确报告，已有文件操作不回滚，也不会因此自动重试工具。

恢复后使用当前模型配置及当前系统提示。模型或 API 地址变化时，保留正文和工具记录，移除旧模型原生状态并重置上下文占用估算；不会把旧配置覆盖到本次显式设置。思考与显示偏好继续遵循原有配置和偏好恢复规则。接口自动查询的上下文上限重新获取；会话内手动设置的上限在同一模型下恢复，本次显式 `--context-window` / `LLM_CONTEXT_WINDOW` 优先。

Docker 模式恢复原工作副本及回写基线，未回写的修改不会丢失。重启不会重新建立旧容器或恢复其中的进程，工具仍按当前沙箱策略执行。已有未回写修改需要检查后手动 `/apply`，避免重启绕过失败检查；干净副本后续任务仍可自动回写。宿主项目在退出期间的外部修改不会自动合并到旧副本，回写仍进行冲突检查。原副本丢失或记录损坏时会提示修复或使用 `--new-session`，不会悄悄覆盖旧记录。同项目同时只允许一个 Agent 会话运行。

支持 `/compact` 手动压缩和按预算自动压缩；先归档原始消息，再保存摘要及近期原文，重启直接恢复压缩后的上下文，见[上下文压缩与历史回查](context-compaction.md)。交互模式与单任务模式使用同一组模型参数和环境变量，CLI 会自动加载用户及项目配置。

## 保存位置

默认根目录是 `${XDG_STATE_HOME:-~/.local/state}/repo-agent/sessions/`，以解析符号链接后的项目绝对路径的 SHA-256 划分项目：

```text
sessions/
└── <项目路径哈希>/
    ├── index                  # 名称、递增序号、创建与活动时间
    ├── execution.sqlite3      # 工具执行意图、开始、结果及身份关联
    ├── .pending-save          # 发布未完成时保留的提交记录
    ├── history.sqlite3        # 原始消息档案、稳定引用与有序快照（首次归档时创建）
    ├── latest.json            # 默认恢复的会话 ID
    ├── <会话ID>.json           # 上下文及界面状态快照
    ├── <会话ID>/
    │   ├── chat.log           # 对话和必要提示
    │   ├── trace.log          # 跨重启的可读执行日志
    │   ├── trace.jsonl        # 跨重启的结构化执行事件
    │   └── compaction-diagnostics/  # 压缩失败候选及引用映射，文件名为诊断 ID
    ├── .lock                  # Agent 执行锁
    └── .metadata.lock         # 短时元数据锁
```

`index` 是名称的权威来源。改名不改变内部 ID、序号、日志路径或 `latest.json`；下一次快照也会使用新名称。同一会话不断更新自己的快照，新建会话保留旧快照和日志。查看日志的命令及 `cat` / `tail` 示例见[日志说明](logging.md#查看日志)。

会话快照、日志和沙箱工作副本是不同数据。快照只保存沙箱路径，不包含副本文件；完整保留未回写文件时，还要保留对应的沙箱目录。状态记录包含对话文本、工具结果及模型原生状态，配置中的 API Key 不作为会话元数据保存。

## 旧记录与异常情况

旧快照在首次查询或恢复时按文件保存时间分配固定序号和默认名称；旧可见对话可导入 `chat.log` 一次。旧执行日志没有可靠的会话关联，不会猜测归属；查看时提示到原 `logs/` 或 `AGENT_LOG_DIR` 查找。

记录损坏、目录不可写、日志丢失或沙箱路径失效时会明确报错。不能恢复时可使用 `--new-session` 创建新会话，旧快照保留；项目索引损坏仍需修复索引。移动项目目录会改变项目标识，不会自动迁移旧记录。没有旧会话的自动过期、归档管理或删除命令；上下文压缩的原文自动归档是独立机制，不会删除旧会话。

会话、索引和最新指针通过可重放提交记录修复部分发布；具体提交顺序、版本与平台边界见[多文件提交与修复](execution-ledger.md#多文件提交与修复)。
