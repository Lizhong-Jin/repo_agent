# 会话管理

[返回 README](../README.md) · [日志查看](logging.md)

一个会话可以包含多条用户任务，也可以跨多次程序启动继续。程序按项目保存会话，默认恢复该项目最后一次会话；当前没有按序号恢复任意旧会话的命令。会话序号可用于列表、改名和日志查询。

## 会话命名与管理

新会话分配永久 ID 和项目内递增序号；未命名时显示为 `会话 1`、`会话 2`。自定义名称也占用一个序号，序号不回收（启动失败时可能跳号）。恢复上次会话、每次输入任务、`/clear` 都不会分配新名称或序号。

```bash
repo-agent --new-session --name "修复登录问题"
repo-agent --new-session                         # 默认名称
repo-agent sessions list
repo-agent sessions rename 12 "登录问题排查"
repo-agent sessions list --root /path/to/project
```

首次启动没有历史记录的项目时，也可以直接传 `--name`。已有会话时，`--name` 须配合 `--new-session`；恢复会话的改名使用 `/rename` 或 `sessions rename`。

界面命令：`/new [名称]`、`/rename 新名称`、`/sessions`、`/logs [序号] --tail 100`。名称支持中文和空格，长度为 1–80 个字符，不能包含换行或控制字符。支持重名；命令优先按序号或完整 ID 查找，再按名称精确查找，同名时列出候选序号。`latest` 表示默认恢复的会话。

TUI 顶部常驻会话名称与序号，按 **F2** 编辑名称，Enter 保存、Ctrl+C 取消；编辑前的输入草稿会保留。也可以用 `/rename` 改名。普通终端在每次输入前显示名称。另一个终端改名后，TUI 会在约一秒内更新标题；改名不会修改上下文、序号、日志路径或默认恢复的会话。

列表显示序号、名称、最近活动时间、是否正在运行以及是否默认恢复。查看列表和日志无需模型配置或 Docker，不占用 Agent 的执行锁；运行时也能在另一个终端查看或改名。管理命令支持 `--root`，也支持 `repo-agent --root /path sessions list`。

## 保存、恢复与新会话

```bash
repo-agent                        # 默认恢复当前项目的最后一次会话
repo-agent --new-session          # 启动全新会话，保留旧会话记录
repo-agent --root /path/to/project # 恢复指定项目的最后一次会话
repo-agent '继续完成刚才的修改'      # 单次任务也会恢复并保存会话
```

会话内 `/new` 保存旧会话、清空显示历史与模型上下文并重置累计用量；文件修改和当前沙箱副本保留。`/clear` 清空模型上下文，保留显示历史和累计用量，清空结果也会保存；此前压缩产生的原文档案保留。没有历史记录的项目自动创建会话。不同项目相互隔离，以解析符号链接后的项目绝对路径作为标识；同一目录的符号链接共用会话，移动项目目录后视为不同项目。

会话记录目录权限为 `700`，文件权限为 `600`；快照采用临时文件和原子替换保存。会话状态目录受文件工具与沙箱导入/回写保护。

每个任务执行前记录未完成标记，任务结束后保存有效历史，正常退出时再次保存。未传入新任务时，重启恢复状态后等待用户输入；显式传入任务时执行该新任务，不会重放历史工具调用。强制终止或断电后恢复到最后保存的完整任务，并说明中断任务可能已执行部分文件操作；未完成任务内部的全部工具结果不保证保存。用量以已保存的统计为准。保存失败会明确报告，已有文件操作不回滚，也不会因此自动重试工具。

恢复后使用当前模型配置及当前系统提示。模型或 API 地址变化时，保留正文和工具记录，移除旧模型原生状态并重置上下文占用估算；不会把旧配置覆盖到本次显式设置。思考与显示偏好继续遵循原有配置和偏好恢复规则。接口自动查询的上下文上限重新获取；会话内手动设置的上限在同一模型下恢复，本次显式 `--context-window` / `LLM_CONTEXT_WINDOW` 优先。

Docker 模式恢复原工作副本及回写基线，未回写的修改不会丢失。重启不会重新建立旧容器或恢复其中的进程，工具仍按当前沙箱策略执行。已有未回写修改需要检查后手动 `/apply`，避免重启绕过失败检查；干净副本后续任务仍可自动回写。宿主项目在退出期间的外部修改不会自动合并到旧副本，回写仍进行冲突检查。原副本丢失或记录损坏时会提示修复或使用 `--new-session`，不会悄悄覆盖旧记录。同项目同时只允许一个 Agent 会话运行。

支持 `/compact` 手动压缩和按预算自动压缩；先归档原始消息，再保存摘要及近期原文，重启直接恢复压缩后的上下文，见[上下文压缩与历史回查](context-compaction.md)。交互模式与单任务模式使用同一组模型参数和环境变量，CLI 会自动加载用户及项目配置。

## 保存位置

默认根目录是 `${XDG_STATE_HOME:-~/.local/state}/repo-agent/sessions/`，以解析符号链接后的项目绝对路径的 SHA-256 划分项目：

```text
sessions/
└── <项目路径哈希>/
    ├── index                  # 名称、递增序号、创建与活动时间
    ├── history.sqlite3        # 原始消息档案、稳定引用与有序快照（首次归档时创建）
    ├── latest.json            # 默认恢复的会话 ID
    ├── <会话ID>.json           # 上下文及界面状态快照
    ├── <会话ID>/
    │   ├── chat.log           # 对话和必要提示
    │   ├── trace.log          # 跨重启的可读执行日志
    │   └── trace.jsonl        # 跨重启的结构化执行事件
    ├── .lock                  # Agent 执行锁
    └── .metadata.lock         # 短时元数据锁
```

`index` 是名称的权威来源。改名不改变内部 ID、序号、日志路径或 `latest.json`；下一次快照也会使用新名称。同一会话不断更新自己的快照，新建会话保留旧快照和日志。查看日志的命令及 `cat` / `tail` 示例见[日志说明](logging.md#查看日志)。

会话快照、日志和沙箱工作副本是不同数据。快照只保存沙箱路径，不包含副本文件；完整保留未回写文件时，还要保留对应的沙箱目录。状态记录包含对话文本、工具结果及模型原生状态，配置中的 API Key 不作为会话元数据保存。

## 旧记录与异常情况

旧快照在首次查询或恢复时按文件保存时间分配固定序号和默认名称；旧可见对话可导入 `chat.log` 一次。旧执行日志没有可靠的会话关联，不会猜测归属；查看时提示到原 `logs/` 或 `AGENT_LOG_DIR` 查找。

记录损坏、目录不可写、日志丢失或沙箱路径失效时会明确报错。不能恢复时可使用 `--new-session` 创建新会话，旧快照保留；项目索引损坏仍需修复索引。移动项目目录会改变项目标识，不会自动迁移旧记录。没有自动过期、归档或删除命令。
