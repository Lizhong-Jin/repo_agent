# 会话任务队列

[文档首页](index.md) · [交互命令](usage.md) · [会话恢复](sessions.md)

每个会话拥有一条持久化、串行执行的队列。TUI 正在执行时，输入普通文本并按回车会追加任务；这条文本不会发给当前任务。任务开始时读取最新有效上下文，因此后一项可以使用前一项的结果。

用户任务的串行队列与[工具并发](tools.md#并发调度策略)是不同层次：一项任务内部可以并发读取或查询，整个任务、回写、进程清理和会话提交完成后才推进下一项。

## 常用操作

| 输入 | 行为 |
| --- | --- |
| `/queue` 或 `/queue list` | 查看执行项、等待项和最近 10 条结束记录 |
| `/queue add 任务文本` | 追加任务；TUI 普通文本输入等效 |
| `/queue pause` | 暂停后续调度，让当前任务正常收尾 |
| `/continue` | 一步继续最近因调用上限暂停的任务，再获得当前 `max_steps` 轮预算，优先于等待项执行 |
| `/queue resume` | 明确恢复队列；不会自动重试失败或中断的旧任务 |
| `/queue edit 3 新文本` | 修改等待中的第 3 号任务 |
| `/queue remove 3` | 移除等待中的第 3 号任务，保留取消记录 |
| `/queue move 3 1` | 将第 3 号任务移到等待队列的第 1 个位置 |
| `/queue clear` | 移除全部等待项；不停止当前任务、不删除历史记录 |
| `/queue retry 3` | 根据未完成的历史任务新建一项，保留原记录和来源编号 |

任务编号在会话内保持稳定，位置从 1 开始。只有等待项允许编辑、移动、移除。斜杠控制命令不能排队。

例如先暂停，再整理一个批次：

```text
/queue pause
/queue add 检查当前测试失败的原因
/queue add 根据分析修复问题并运行相关测试
/queue add 总结本次修改
/queue resume
```

普通行模式也支持这些命令，但执行时不并发读取输入。需要在运行中追加或调整任务时使用 TUI。

## 暂停、取消与恢复

只有任务正常完成、所需自动回写成功、进程清理没有未确认项，并且结果保存成功，才会自动开始下一项。模型报错、达到轮数上限、用户取消、自动回写失败、进程清理未确认都会暂停队列，保留等待任务。

- 执行中按 **Ctrl+C**：取消当前任务并暂停队列；等待网络、工具及进程清理收尾。
- `/queue pause`：只停止后续调度，当前任务继续。
- 取消和重试不会撤销文件修改。重试前检查文件和工具结果；重试会重新执行完整任务，并非从中断位置续跑。
- 达到轮数上限后，输入 `/continue` 即可继续，无需手动添加“继续”或 `/queue resume`。续接任务继承有效上下文和工具结果，自动放到等待队列首位，再获得当前配置的 `max_steps` 轮预算；再次耗尽时可再次使用此命令。配置值本身不会累加，续接正常完成后继续执行其他等待项。
- 续接有独立任务编号、执行尝试和 `continuation_of` 来源关联，保留原任务的上限记录。重启后仍可使用；保存失败时重发命令不会重复创建续接项。命令只接受最近执行项因 `max_steps` 暂停且上下文仍存在的情况，不适用于用户取消、普通失败或进程清理未确认。Docker 因尚未完成而暂缓自动回写的上限任务也可续接。
- 清理结果为“未确认”时，本进程拒绝恢复队列。退出、核实残留进程后重新启动，再检查队列。Windows 的部分进程树清理仍属于尽力终止，不能承诺所有后代进程都退出。

重新启动后，保存的等待项处于暂停状态；此前执行中但没有持久化结束结果的任务标记为“中断”，不自动重放。原来已完成的任务不会再次执行。单次命令行任务发现已有等待队列时拒绝插队，请进入交互模式处理或使用 `--new-session`。

存在执行项或等待项时，`/new`、`/clear`、`/model`、`/thinking` 等改变执行上下文的操作会被拒绝；先执行完或移除等待项。TUI 思考显示的展开、折叠不影响执行配置，可继续使用。

## 保存与边界

队列与消息历史、执行中标记保存在同一份会话快照中，沿用项目级排他锁和原子替换。入队保存后才确认接收；执行前保存开始标记；收尾时统一保存上下文和任务结果。保存失败立即停止调度，已发生的文件操作不会回滚。修复磁盘或权限后先查看 `/queue`，再明确恢复；无需重复提交已经出现在队列中的任务。

每项任务保存稳定 ID、编号、正文、时间、状态、一次执行记录及结果摘要。执行记录包含模型标识、轮数、输出额度、思考设置、执行模式和回写策略，不保存 API Key。结果分别记录任务状态、回写结果、进程清理和已报告的工具修改；任意子进程的副作用无法保证全部枚举。

本版是单进程、单消费者的会话队列，没有后台守护进程、多项用户任务并行执行、定时调度或自动重试。每个会话最多保存 1000 项，每条任务最多 100000 字符；达到上限后使用新会话。队列暂停时退出即可保留任务，不需要让终端继续运行。

## 开发边界

- `agent/task_queue.py`：纯状态及快照校验，不依赖终端或执行后端。
- `cli/task_controller.py`：统一入队、调度、取消、恢复和结果提交；TUI、行模式、单次入口共用。
- `cli/task_execution.py`：仅执行一项任务，返回包含回写和清理结果的 `TaskOutcome`。
- `SavedConversation`：与历史一起保存队列；后台自动压缩和主线程入队共用状态锁，避免互相覆盖快照。
- TUI 工作线程仍只通过事件投递更新界面；调度和收尾在界面主循环推进，退出时先停止调度再等待当前工作线程结束。

后续增加其他前端时优先复用控制器。只有引入独立工作区及明确的修改合并策略之后，才考虑多消费者；独立存储进程则需要租约与事务认领，不能直接复用当前内存中的执行标记。

工具调用还会同步提交独立的[执行账本](execution-ledger.md)。账本写入失败或工具异常导致效果未知时，当前任务停止并暂停队列；`/ledger` 可查看核实依据。

切换已有会话使用 `/switch 序号或名称`。当前有等待项时先 `/queue pause`；等待项会随原会话保存，切回后需 `/queue resume`。任务运行或收尾期间不能切换。目标会话自己的队列恢复后同样保持暂停，详见[会话选择与切换](sessions.md#选择与切换已有会话)。
