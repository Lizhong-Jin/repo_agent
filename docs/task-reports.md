# 任务交付报告

每个通过任务队列执行的任务，在完成、失败、取消或达到模型调用轮数上限后，自动展示交付报告摘要。单次 `--task`、行交互和 TUI 使用同一数据与生成流程。报告不调用模型，也不会加入模型工作上下文。

## 查看

```text
/report                         # 当前会话最近一次任务的详细报告
/report 3                       # 当前会话任务 #3
/report 3 --diff                # 任务前后差异，以及各次工具操作差异

repo-agent sessions report
repo-agent sessions report 2 --task 3 --diff
repo-agent --root /path/to/project sessions report 2 --task 3 --json
```

终端命令中的 `2` 是会话序号，也可用名称、完整会话 ID 或 `latest`；`--task 3` 是该会话的任务编号。无需模型配置即可查询。TUI 在对话区展示收尾摘要，使用 `/report` 或 F3 打开独立报告页；行交互与命令行仍输出文本报告。

界面输出最多 100000 字符；超过时明确提示截断。JSON 导出包含保存的快照、差异、命令参数、输出摘录、账本引用和排除范围；它不恢复原工具已经丢弃的输出。完整已捕获工具结果通过执行账本和 `read_tool_result` 的 `result_ref` 回查，规则见[执行账本](execution-ledger.md)。

## TUI 报告页

- **打开与返回**：`/report [任务编号]` 或 F3（Mac 通常为 fn+F3）。`/report 3 --diff` 直接打开任务 #3 的文件变化。Esc、F3 或“返回”回到对话；用快捷键打开时保留未发送草稿和原来的聊天浏览位置。
- **任务与分类**：“上一任务”“下一任务”浏览当前会话中已启动的任务；“刷新”重新读取保存的报告。页面提供总览、文件变化、工具操作、验证清单、执行记录五类。总览包含任务状态、未验证项、快照范围与性能数据。
- **选择与详情**：鼠标点击条目，或 Tab 切换焦点、↑↓ 选择。Enter 从列表进入详情；PgUp/PgDn 翻阅详情，差异中的增加和删除行使用不同颜色。窄终端自动改为上下布局。
- **原始证据**：选中工具操作或执行记录后点击“原始结果”，按保存的引用读取账本。验证项目读取最近一次关联执行的结果，全部执行引用仍显示在详情中。没有结果引用的项目明确提示不可回查；宿主回写验证不会伪装成模型工具结果。
- **人工验收**：在验证清单中选择项目，点击“验收通过”“未通过”或“待验收”，填写备注后点击“保存意见”。状态不会改变原始命令结论；Esc 先取消未保存的意见，再次 Esc 返回对话。保存失败保留备注，报告版本已变化时要求刷新后重新验收。

任务运行期间仍可打开报告页。页面不暂停队列，Ctrl+C 可停止正在运行的任务；编辑验收备注时 Ctrl+C 优先取消该表单。任务结束不会自动切换页面或抢占输入焦点。报告按需读取，不自动轮询；运行中报告只显示已持久化证据，收尾后点击刷新取得最终结果。报告尚未完整保存时禁止验收。

报告浏览、原始结果与表单备注不进入聊天记录或模型上下文，也不触发模型请求。每个详情最多显示 100000 字符并明确标记截断，原报告不被截断。缺失、损坏或旧任务没有报告时显示错误，可切换任务或返回；不会重新扫描当前目录补造历史状态。跨会话请先返回对话使用 `/switch`，或使用 `sessions report` 查询指定会话。

## 结构化验证清单

对需要验证的代码任务，默认系统提示引导模型先调用 `plan_verification` 登记检查，再执行命令。每项包含：稳定 ID、名称、预期行为、类型（`command` 或 `manual`）。命令检查还包含 argv 数组和相对工作目录。任务内最多 100 项；同一 ID 的重复登记幂等，修改检查内容必须用新 ID，旧检查与结果保留。

报告只关联**同一任务执行尝试内，登记之后执行的 `run_command`**：argv 必须完全一致，工作目录按规范化后的相对路径匹配。任意成功命令、其他目录的同名命令、其他任务的结果、登记前的历史命令都不能充当该项证据。多次执行保留全部记录，最近一次结果决定当前检查状态。

状态包括：尚未执行、检查命令通过、失败、超时、文件变化需重新验证、结果未确认、待人工检查。检查命令通过要求退出码为 0、无清理未确认标记，并且检查前后和任务结束的快照范围完整且内容一致。命令必须自行包含有效断言；程序不证明命令确实覆盖了声明的所有预期行为。`run_shell`、`run_python` 仍在原始执行记录中展示；要关联清单，可改用 `run_command` 调用相应解释器或项目测试脚本。

模型只能提出计划，不能设置检查结果或用户验收状态。命令结果与用户验收分别显示。例如，一个命令失败的项目即使用户填写“确认通过”，原始失败仍然可见。

### 用户验收

```text
/report 3 --accept session-switch accepted --note "已人工切换并确认恢复内容"
/report 3 --accept session-switch rejected --note "切换后名称显示不正确"
/report 3 --accept session-switch pending --note "等待修复后复查"

repo-agent sessions report 2 --task 3 --accept session-switch accepted --note "人工复查通过"
```

必须提供备注。仅能验收已完整保存的报告中的现有项目。验收意见追加保存在同目录 `reviews-<attempt_id>.json`，不会重写机器报告或执行账本；JSON 导出保留意见历史。意见绑定报告内容摘要，报告内容改变后旧意见不自动用于新版本。

此入口记录 UI/CLI 操作者提供的意见，不进行外部身份认证，也不是安全审批系统。模型工具不提供验收接口。人工意见针对报告中的历史版本，不代表此后磁盘文件一直未变。重试和续接任务使用各自的清单与报告，不能跨任务借用通过记录。

## 两种不同的差异

- **任务期间观察到的变化**：实际开始执行时与收尾时的文件状态对比，包括未跟踪文件；不用 Git HEAD，因此不会把任务开始前已有的未提交修改算成本次新增变化。此项不判断作者。
- **已记录的工具操作**：`write_file`、`edit_file`、`apply_patch`、`delete_file`、`move_file` 在实现内部提供的文件操作证据，包括前后哈希、可用的文本差异和账本引用。它们不保证覆盖所有文件变化。

操作差异基于工具读取的输入和写入的结果；共享目录中仍可能存在并发编辑，不能据此证明工具独占了整个文件。比较最终内容时只显示“一致”“之后存在其他变化”或“未确认”，不会推断其他变化一定来自用户。多次操作同一文件保留各次记录；改完又恢复原状时，即使最终差异为空，也保留操作历史。

补丁部分提交后失败，报告保留已提交文件的操作和失败记录。删除或移动只有路径操作证据；移动目的文件没有字节写入回执时，不虚构最终哈希或确认结果。任意命令、脚本及后台进程产生的变化只作为观察结果，命令名或标准输出中的声明不是修改归属证据。目录创建不属于第一版的文件内容差异。

## 命令与验证结果

报告列出 `run_command`、`run_python`、`run_shell` 的实际调用参数、返回码、超时和清理信息、输出摘录及结果引用，区分成功、失败、未执行和未知状态。第一版不自动把任意命令认定为测试，也不从自然语言输出提取测试通过数量。

每次进程工具调用前后采集检查范围的内容指纹，在收尾报告中保存，并与任务结束状态核对：

- 前、后及结束时均完整且内容一致：显示“检查范围内内容一致”。这是有边界的观察，不证明运行过程中从未发生临时修改。
- 发现文件变化：显示“文件有变化，需重新验证”。第一版保守地比较整个检查范围，不分析测试依赖；生成新文件也可能触发提醒。
- 扫描不完整、旧回执缺少指纹或任务中断：验证有效性为“未确认”。

退出码 0 仅表示命令成功，不代表任务需求全部满足，也不代表执行过全部测试。没有命令记录时显示“无已记录的命令验证证据”。需求覆盖和未登记的人工检查不自动判定；已登记的人工检查显示待验收，可由用户单独确认。

Docker 下分别保存副本和宿主目录的观察差异，并显示本次回写结果。本次真实执行的最终回写验证另存到报告中，来源标记为 `host_final_verification`，不是模型工具调用，也没有模型工具结果引用。其有效性暂标为未知；不读取上次任务遗留的 `verification.json` 冒充本次验证。

## 保存、恢复与限制

报告保存在项目私有会话状态目录下：

```text
<项目状态目录>/reports/<session_id>/<attempt_id>.json
```

默认项目状态目录为 `${XDG_STATE_HOME:-~/.local/state}/repo-agent/sessions/<项目绝对路径的 SHA-256>/`，与 `execution.sqlite3` 同级。备份会话时应一起保存 `reports/`。报告包含源码差异，按私有数据保护；文件权限为 0600，目录创建权限为 0700。

开始时先保存基线与 `incomplete` 报告，收尾后原子替换为完成的报告。每个执行尝试有独立标识，并保留重试及续接关系。清空或压缩上下文不删除报告；切换会话后可通过会话选择器查看旧报告。

异常退出时查询报告只使用已保存基线和账本，不重新扫描当前目录伪造历史结束状态。执行工具后、回执持久化前崩溃时，仍遵循账本的未知效果规则。报告保存失败会在界面和任务结果中明确记录；不会把已执行成功的任务改写成没执行，也不会触发重跑。

快照是逐文件采集，不是整个目录的原子快照。当前固定预算：

- 每次扫描最多 10000 个文件、64 MiB 文件内容、3 秒扫描时间（不承诺中断单次阻塞的系统调用）；单文件读取最多 8 MiB。
- 单个 UTF-8 文本快照最多 64 KiB；每次目录快照保留的文本总量最多 4 MiB。
- 单份文本差异最多 32768 字符，超过时标记截断；二进制、过大内容或缺少前后文本时标记无法展示文本差异。
- 遵循现有受保护名称和运行时私有目录规则；另跳过 `.venv`、`venv`、`node_modules`、`__pycache__`、`.pytest_cache`、`.ruff_cache`、`build`、`dist`、`target`。报告保存实际排除清单，不把排除范围算作验证覆盖。
- 不跟随符号链接，不读取硬链接或特殊文件；受限文件、读取失败、预算耗尽会明确标记未知或快照不完整。

第一版不提供全目录独占隔离、完整命令写入归属、测试依赖分析、自动重验或报告自动清理。旧版本任务没有历史基线时，不补造报告。

## 实机验收与性能测量

使用项目 Python 运行离线验收脚本，无需模型 API。脚本用固定模型响应驱动真实工具，仅修改临时样例项目；`--project` 指定的目录只用于只读快照和报告性能测量。

```bash
# macOS 或已配置原生执行环境的 Linux / WSL
.venv/bin/python scripts/validate_task_reports.py --mode native --project . --output notes/report-native.json

# Docker：先启动服务并准备包含当前源码的沙箱镜像
.venv/bin/python scripts/validate_task_reports.py --mode docker --image repo-agent-sandbox:v1 --project . --output notes/report-docker.json
```

没有可用原生后端或 Docker 镜像时返回非零，不自动退回未隔离执行。验收包括：同期修改归属、任务前已有修改、检查失败与未执行、验证过期、账本引用、取消、重启和切换会话；Docker 额外检查副本与显式回写。进程强制退出场景使用真实子进程和本地文件工具验证持久化恢复，不宣称覆盖所有内核或断电故障。依赖测试镜像中当前版本的文件操作回执，旧镜像可能无法通过检查。

输出 JSON 含平台、实际执行环境、验收结果及三次重复测量：100 文件、2000 文件样本和可选真实项目的快照耗时、完整报告生成和保存耗时、报告文件大小。报告本身也记录扫描耗时、读取字节、文本保留量和收尾构造时间；`finish_build_seconds` 不含最终写盘，脚本测得的 `finish_seconds` 包含写盘。测量有缓存和宿主负载影响，不是性能保证。

WSL 脚本必须在 WSL 内运行，结果中的平台信息用于区分真实环境。未执行的环境应标记未验证，不能用 macOS 或普通 Linux 容器的结果代替。
